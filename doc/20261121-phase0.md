## 2. CST ダンプ検証

- `PlayerController.cs`: `nodes=88 / tokens=126 / complete=True / recovered=0`。
- 宣言ノードは `NamespaceDeclaration` / `ClassDeclaration` / `InterfaceDeclaration` /
  `FieldDeclaration` / `MethodDeclaration` / `PropertyDeclaration` を `NodeKind` の数値
  （Roslyn `SyntaxKind` と同一）で直接抽出できた。例:
  `ClassDeclaration PlayerController @(5,4)`、`MethodDeclaration GetConfiguredHealth @(9,8)`。
- 名前抽出は「最初の Identifier トークン」では不正確だった（属性名や戻り値型が拾われる）。
  種別ごとに区切りトークンを判定する方式に修正し、フィールド `config` / メソッド `Create`
  などを正しく取得できることを確認（`CsffSyntaxAdapter.FindIdentifier`）。
- `UNITY_EDITOR` を `parseWith` に渡すと CST が変化（nodes 29 → 36、メソッド 2 → 3、
  `OnEditorTick` が出現）。`#if` 分岐の seeded symbols は有効。
- 日本語コメント + 😀 を含むソースで、`public class` の UTF-16 offset 43 が
  `SourceSpan` と `LineMap` の往復で一致。UTF-16 位置ズレなし。
- 不完全ソース `public class Broken { void M(` は `IsComplete=false` で落ちずにパース。
  ただし `IncompleteMember` / `BadToken` / `RecoveredTokens` は 0 であり、
  **診断信号は `IsComplete` が主経路**となる（Phase 1 の diagnostics 実装はこれを前提にする）。

## 4. ベースライン比較と判定

比較元: `D:/wsgit/UnityCSharpLSP/doc/20261117-lsbench.md`（同一 `DummyProject`、
ウォーム状態、同一マシン）。

| 指標 | 現状 median | 目標（/10） | 本実装 p50 / p95 | 判定 |
| :--- | ---: | ---: | ---: | :--- |
| completion | 38.957 ms | 3.896 ms | 44.5us / 67.0us | 余裕で合格 |
| didChange→diagnostics（代理値は diagnostics/open） | 5.118 ms | 511.8 us | 44.5us / 67.0us | 合格 |
| hover | 0.718 ms | 71.8 us | 再パース経路なし | 対象外（キャッシュ世代で対応） |

**判定: GO。** 代表的な Unity スクリプト（817 文字）の全文再パースは p50 44.5us で、
現状の diagnostics の 1/10（511.8us）に対して約 11 倍のマージンがある。
8 KB でも p50 290.6us で目標内。80 KB 以上では diagnostics/10 を超えるが、
completion/10（3.896 ms）は 300 KB でも p50 2.867ms で維持できている。

## 5. 注意点・Phase 1 以降への引き継ぎ

- 現状の didChange→publishDiagnostics の実測値は lsbench に無いため、`diagnostics/open`
  を代理値として使用した。Phase 4 で実 didChange レイテンシを測り直すこと。
- csff にはインクリメンタルパース API が無いため、didChange ごとに全文再パースする。
  巨大ファイル（80 KB 超）が編集対象になるケースは 11 節の差分再パース（最終手段）の
  候補として残す。通常の Unity スクリプトサイズでは問題にならない。
- 診断は `IsComplete` を主信号とし、`IncompleteMember` / `BadToken` は補助として扱う。
- `NamespaceDeclaration` の名前抽出は先頭識別子（例: `Game.Runtime` → `Game`）であり、
  完全修飾名は Phase 2 の `SymbolIndex` 側で組み立てる必要がある。
- ベンチは `dotnet run --project benchmarks/Phase0.Bench -c Release -- --file <path>`
  で再実行可能。`--warmup` / `--iterations` で条件を変更できる。
